# Android Size Optimisation

## 1. Current state (verified)

- Managed workflow: no `android/` directory; it is generated by `npx expo prebuild` and git-ignored.
- `app.json` has no `android.package`; `eas.json` does not exist; `expo-build-properties` is not installed. Consequently **no Android release artefact has ever been produced from this repository state**, and no APK/AAB size is measured (see `size-baseline.md` §6).
- Expo SDK 57 defaults that apply once prebuild runs (from the Expo Gradle template, to be confirmed in the generated `android/gradle.properties` and `android/app/build.gradle` in Phase 0):
  - Hermes enabled; bytecode compiled at build time.
  - New Architecture enabled (only option).
  - `reactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64`.
  - `android.enableProguardInReleaseBuilds=false` and `android.enableShrinkResourcesInReleaseBuilds=false` (R8 code shrinking and resource shrinking **off**).
  - `android.enablePngCrunchInReleaseBuilds=true`.
  - Bundle compression: the template packages the JS bundle uncompressed or compressed depending on `android.enableBundleCompression`; confirm the SDK 57 default in the generated project.
- Native modules that will be compiled in: 23 Expo modules and 11 community modules (baseline §2), including four that the app never imports (expo-audio, expo-linear-gradient, expo-web-browser, @react-native-community/slider) and `react-native-svg` used only for two static icons.

## 2. What each size figure means (and why one number is never "the size")

| Figure | Definition | Who sees it | How to obtain |
|---|---|---|---|
| AAB size | The Android App Bundle file uploaded to Play. Contains all ABIs, densities, and languages in split form | Developer only | `./gradlew :app:bundleRelease` |
| Play download size (per device) | Bytes transferred to a given device: base module + that device's ABI, density, and language splits, compressed by Play | End user (Play listing shows the size for the viewing device) | `bundletool get-size total --apks=app.apks --dimensions=ABI` |
| Installed size (per device) | On-device footprint after install: extracted APK splits, DEX (possibly compiled to OAT), uncompressed native libs if `extractNativeLibs`/legacy packaging is used | End user (Settings → Apps) | `adb shell du` on `codePath` (deferred; device required) |
| Universal APK | One APK with every ABI and density; the largest possible artefact | Sideloading / QA | `bundletool build-apks --mode=universal` or `assembleRelease` |
| ABI-specific APK | An APK built for one ABI (for example arm64-v8a) | QA, some distribution channels | `bundletool build-apks --mode=default` then extract, or Gradle `splits.abi` |
| Debug APK | Unminified, dev-menu, Flipper-free but with dev tooling | Developers | `assembleDebug`; never a size target |

Reporting rule for this initiative: always publish (a) AAB size, (b) arm64-v8a download size, (c) armeabi-v7a download size, (d) universal APK size. Never present a single number as "the app size".

## 3. Optimisations

### 3.1 Remove unused native modules (C-04, C-09)

Removing expo-audio, expo-linear-gradient, expo-web-browser, and slider removes their Kotlin/Java classes, resources, manifest merges, and any bundled `.so`. Removing react-native-svg removes its classes and its Fresco imagepipeline dependency declaration (Fresco itself remains, as RN core uses it). Size effect: NOT MEASURED; measure by diffing the AAB before and after with `bundletool` and APK Analyzer.

### 3.2 R8 code shrinking and resource shrinking (C-14)

Mechanism: add `expo-build-properties` as a dependency and configure in `app.json`:

```json
["expo-build-properties", {
  "android": {
    "enableProguardInReleaseBuilds": true,
    "enableShrinkResourcesInReleaseBuilds": true
  }
}]
```

The exact property names must be verified against `node_modules/expo-build-properties/build/pluginConfig.d.ts` after installation (Phase 5, task 1); the LLD lists the alternates that different SDK versions have used (`enableMinifyInReleaseBuilds`).

What it does: R8 removes unreachable Java/Kotlin classes and methods (Compose, media3 DASH, Glide integrations that are never called, Kotlin stdlib) and optionally obfuscates; resource shrinking removes unreferenced Android resources. Expo modules and RN ship consumer keep rules, and Expo's template adds `proguard-rules.pro` defaults.

Risks and their checks:

| Risk | Detection | Mitigation |
|---|---|---|
| Reflection-based module registration stripped | App crashes at launch or a module is "not found" | Expo modules ship `consumer-rules.pro`; verify launch on emulator (not a physical device) after the build |
| media3/ExoPlayer HLS or OkHttp datasource classes stripped | HLS fails to play, MP4 plays | Full playback regression on emulator: demo MP4, demo HLS, live/YouTube fallback; add `extraProguardRules` for `androidx.media3.**` only if a failure is reproduced |
| WebView JS interface stripped | `LiveEmbedView` blank | Regression row; `react-native-webview` ships keep rules |
| Crash stack traces obfuscated | Unreadable production stacks | Keep `mapping.txt` from `android/app/build/outputs/mapping/release/`; upload alongside the build |

Size effect: NOT MEASURED until Phase 5. Do not quote typical R8 percentages.

### 3.3 ABI strategy

- Keep `reactNativeArchitectures` at the default four for the AAB: Play delivers only the matching ABI, so x86/x86_64 cost nothing on real devices and keep emulator testing possible.
- Do **not** hand-build ABI-split APKs for release; Play splitting is the delivery mechanism.
- For QA sideloads, build per-ABI APKs from the AAB with `bundletool` rather than a universal APK, so QA numbers match what users download.

### 3.4 Hermes and bundle packaging

- Hermes stays on (default). A Hermes bytecode bundle is larger than minified JS on disk but avoids JIT parsing and lowers startup time; this is a deliberate size-for-startup trade.
- The JS bundle is stored inside the APK under `assets/`. Whether it is stored compressed depends on the template's `enableBundleCompression` setting; confirm the SDK 57 default in Phase 0 and record it. Compressed storage lowers download size but forces extraction at startup on some Android versions; do not change without measuring cold start on a device (deferred).

### 3.5 Resources and manifest

- Launcher and adaptive icons are generated at fixed densities by prebuild; `enablePngCrunchInReleaseBuilds` (default) already optimises them.
- Manifest permissions come from modules. Removing expo-audio removes `RECORD_AUDIO`-related and `MODIFY_AUDIO_SETTINGS` merges if present; removing expo-web-browser removes its custom-tabs query. Verify with `aapt2 dump badging` on the built APK (Phase 9) and record the permission list before and after — a security benefit as well as size.

### 3.6 Duplicate native libraries

Not measurable until a build exists. In Phase 9 list `lib/arm64-v8a/*.so` and confirm no library appears under two names or versions (for example two `libc++_shared.so` would indicate a packaging problem; `pickFirst` rules from the template normally prevent this).

## 4. Local build recipe (no device required)

Prerequisites: D-1 (`android.package`), Java 17 (present), Android SDK (present at `%LOCALAPPDATA%\Android\Sdk`; set `ANDROID_HOME` to it), `bundletool` jar downloaded from GitHub releases.

```
npx expo prebuild -p android --clean
cd android
./gradlew :app:bundleRelease
java -jar bundletool.jar build-apks --bundle=app/build/outputs/bundle/release/app-release.aab --output=../.size-reports/app.apks --mode=default
java -jar bundletool.jar get-size total --apks=../.size-reports/app.apks --dimensions=ABI
java -jar bundletool.jar build-apks --bundle=app/build/outputs/bundle/release/app-release.aab --output=../.size-reports/universal.apks --mode=universal
```

Record: AAB bytes, `get-size` MIN/MAX per ABI, universal APK bytes, `unzip -l` grouped by `lib/`, `assets/`, `classes*.dex`, `res/`. Save the report as `.size-reports/<date>-<label>.md` (git-ignored) and copy the summary table into `docs/size-optimization/optimization/size-baseline.md` §6.

Alternative without a local Android SDK: `eas build -p android --profile production` (cloud) or `--local`. Requires D-2 and an Expo account; the artefact is the same AAB.

## 5. iOS note

Android is the primary target of this document, but the same principles apply: App Store thinning delivers per-device slices; the only iOS-specific size levers identified are the removal of unused pods (C-04, C-09) and the optional `expo-image.disable-libdav1d` Podfile property (experiment X-3, D-6). No iOS build can be produced on this Windows machine; measure via EAS.
