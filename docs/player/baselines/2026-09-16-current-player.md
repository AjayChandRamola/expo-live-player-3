### Method deviations

The plan's two commands did not work against this project and were replaced
with equivalents that do. Increment 7 must use the same replacements or the
comparison is meaningless.

1. **`--no-bytecode` added to the export.** By default `expo export` emits
   Hermes bytecode (`entry-<hash>.hbc`, 3.45 MB). `source-map-explorer` needs
   JavaScript, and bytecode size does not map cleanly onto source files anyway.
   With `--no-bytecode` the export is a 3.76 MB `.js` plus a 12.3 MB `.js.map`.
2. **`source-map-explorer` replaced by `scripts/measure-player-bundle.js`.**
   The tool first tried to fetch the map from the bundle's
   `sourceMappingURL`, which points at `http://localhost:8081/…`; passing the
   map explicitly then failed with *"Your source map refers to generated column
   Infinity on line 2, but the source only contains 2417 columns."* The
   committed script decodes the map's VLQ mappings itself and charges each
   generated byte range to the source that produced it. It reports 3,067,711 B
   mapped and 692,217 B unmapped (runtime prelude and polyfills with no source
   attribution); unmapped bytes are excluded from the first-party total, which
   is why the first-party figure is the reliable one.
